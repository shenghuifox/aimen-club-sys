# 隘門國小課後活動管理系統

第一版試辦系統。React 前台部署於 GitHub Pages，Supabase 負責登入、角色授權、業務資料與核銷快照。

## 使用

部署網址：https://shenghuifox.github.io/aimen-club-sys/

登入頁提供五種**假資料角色體驗**：行政、學生、社團老師、班級導師、家長。這些體驗按鈕不是 Auth 帳號；僅修改目前瀏覽器中的假資料，請勿輸入真實個資。

正式測試帳號需先完成下方資料庫安裝與 Auth 建立，再使用帳號密碼登入。

## 第一次安裝 Supabase

1. 在專案 eddaalutgxmanorbfrbm 的 SQL Editor，以管理者依序執行 `supabase/schemas/001_club.sql` **一次**、`002_recurring_and_student_binding.sql`、`003_edit_changes.sql`、`004_bulk_administration.sql`、`005_club_operations.sql`、`006_operations_handover.sql`。由 0.5.0 升至 0.6.0 只需套用 006，先更新資料庫再部署前端。已透過 Supabase 遷移套用者不需重複執行。
2. 在可信任的本機環境設定 `SUPABASE_SECRET_KEY`（伺服器 secret / legacy service_role key），執行 `node scripts/bootstrap.mjs`。金鑰不應貼在聊天、放入 VITE_ 變數或提交 GitHub。
3. 建立後，四個帳號的隨機密碼會保存到本機 `credentials-test-accounts.json`（已加入 gitignore）。帳號會映射成 `帳號@test.aimen.invalid`。此網域僅用於獨立測試，不支援收信或自助重設。
4. admin 登入後建立社團、上課節次、學生名冊，將 stu 綁定學生、hrtr 指定為導師。核對課程與權限後進行試辦。
5. 正式啟用前新增並驗證第二位管理者。第一版允許初始管理者安裝，阻擋管理者數量少於或等於兩位時的撤權。

### Google 登入

目前預設關閉。需於 Google Cloud 與 Supabase 啟用 provider、設定回呼及允許的 GitHub Pages 網址，並以學校未成年學生帳號驗證存取。完成後設 `VITE_GOOGLE_AUTH_ENABLED=true`；登入身分仍須綁定 `club_private.users`，不可自行選角色。

## 開發與部署

Node 24，pnpm 11.25.0。`pnpm install`、`pnpm test`、`pnpm test:db`、`pnpm build`。本機複製 `.env.example` 至 `.env.local`，填入可公開的 Publishable key。禁止把 secret key 放在前台。

main 推送後，`.github/workflows/pages.yml` 執行單元與資料庫測試，再建置部署。GitHub Settings → Pages → Source 須選 GitHub Actions。

## 0.9.1 登入與管理員驗證

- 學生可直接開啟首頁選擇班級及座號，核對 OpenID 數字及姓名末字。新裝置可輸入學校配發的登入碼或開啟原有個人連結。在個人裝置選擇記住登入碼後，下次從首頁登入即可。
- 新建立及重新發行的老師校用帳號，首次輸入「帳號@Amps」和專屬啟用碼，然後自訂新密碼。既有正式密碼沿用至重設。
- 行政帳號需有已確認、可收信的 Email。既有只使用內部別名的行政須由已驗證行政邀請。行政可對其他有效行政寄出重設信，由帳號本人設定新密碼。
- 依序套用 `013_account_verification.sql`，更新兩個登入相關函式，再發布前端。寄信受 Supabase 郵件服務與設定影響。

## 0.9.0 教師與學生入口

- 教職員從「我是老師」使用既有帳號。帳號管理提供行政、班級導師及社團老師三種身分。
- 行政從「學生管理」匯入 CSV 或貼上「班級、座號、姓名、OpenID數字」。OpenID 欄空白時先建立名冊與帳號，日後可個別發行連結。既有同班同座號及姓名會沿用名冊，遇到同座號不同姓名會要求核對。
- 個人登入連結請交付學生本人。開啟後選班級與座號，再輸入既有 OpenID 數字及姓名末字。OpenID 只在本系統核對，為保護個人報名與課表，另核對連結中的隨機憑證。補發會使原連結無效。
- 套用 `011_student_portal.sql` 後部署 `club-account-admin` 及 `club-student-login`。上線時一次性套用 `012_separate_test_term.sql`，以原本的學期識別保存 115test 的歷程，並建立空白 115-1。
- 學校官網可使用 `?embed=calendar` 的獨立公開行事曆。

## 0.8.2 登入頁公開行事曆

- 登入頁左側顯示週一到週日的社團行事曆。手機上方可依日期篩選，或查看整週的課程。
- 公開行事曆列出使用中學期已發布社團的名稱、時間、地點及停課標示。
- 先套用 `supabase/schemas/010_public_calendar.sql`，再部署網頁。

## 0.8.1 批次匯入校用帳號

- 開啟「帳號管理 → 批次匯入校用帳號」，選擇使用中的學期，下載 CSV 範本或貼上試算表資料。每次可匯入 1 至 200 筆，先預覽再確認。
- 學生與家長須用班級、座號及學生姓名比對名冊。教師列的名冊欄位留空。行政管理帳號從「新增校用帳號」逐筆建立。
- 成功列會在結果頁顯示一次初始密碼，可下載交付清單。失敗列可修正後重送，既有帳號不會被覆寫。連線中斷時先查看帳號管理，確認已送出的帳號狀態。
- 延用 0.8.0 資料庫。部署 `club-account-admin` 時一併附上 `school-auth.js` 和 `school-batch.js`，再部署前端。

## 0.8.0 校用帳號

- 行政從「帳號管理」選「新增校用帳號」，填寫帳號、姓名及角色。建立家長或學生帳號時選擇要綁定的學生。
- 由登入服務建立帳號，無須填郵件地址、收信或配置 SMTP。行政在建立時查看一次隨機產生的初始密碼，請將登入資訊直接交付給帳號持有人。
- 社團老師、導師與行政首次使用初始密碼時，須設定新密碼並重新登入。家長與學生可以直接進入系統。密碼至少 8 字元，包含英文字母及數字，最多 72 位元組。
- 校用帳號忘記密碼時請聯絡教導處。其他行政管理員的密碼由持有人或登入服務管理員處理。既有電子郵件登入與匯入繼續提供。
- 升級時先套用 `supabase/schemas/009_school_username_login.sql`，再用 `index.ts` 與 `school-auth.js` 更新 `club-account-admin`，最後部署前端。

## 0.7.2 邀請與密碼回復

- 邀請收件人以完整電子郵件作為登入帳號。收件人驗證一次性連結後自行設定密碼。
- 若原始郵件仍導向 localhost，請勿點擊連結，先從郵件複製完整連結，在正式站選「驗證邀請連結」貼上。如果已使用或過期，可用「忘記或尚未設定密碼」申請新連結，再從郵件複製新連結驗證。
- 託管 Supabase 的 Authentication → URL Configuration 須把 Site URL 與 Redirect URLs 指向 `https://shenghuifox.github.io/aimen-club-sys/`。GitHub Pages 部署不會變更 Supabase 託管專案設定。
- 於託管 Supabase 的 Authentication → Email Templates 將 Invite user 和 Reset password 分別套用 `supabase/templates/invite.html` 及 `supabase/templates/recovery.html`。範本直接導向正式域名，用一次性 token hash 於網站驗證，並要求收件人主動按驗證按鈕。

## 0.7.0 操作更新

## 0.6.0 接手操作

- 學期管理可複製前一期學生、社團、導師及既有帳號綁定。社團複製成草稿；不要沿用舊節次、報名、點名及核銷。核對升班、師資與報名日期後再發布。
- 權限管理可對其他帳號停權、復權並填原因。學校先建立並驗證 Supabase Auth 帳號，承辦再從前台完成身分對應；家長從學生名冊綁定。
- 家長可查已綁定孩子的本週課表、報名結果、異動、繳費並送出請假。導師或行政在既有假單畫面覆核。
- 社團可維護計畫與案號。行政核銷可匯出按社團彙整的活動與核銷總表，原憑證清冊仍使用核銷快照。
- 登入頁的「加到手機主畫面」提供 Safari 和 Chrome 的操作方式。行動裝置可建立線上捷徑。

## 0.5.0 試辦操作

- 異動管理可停課、從已停課節次排定補課，或互換兩個未簽到節次的開始時間。原節次與異動紀錄保留，核銷鎖定和撞課由資料庫查核。
- 社團老師可從首頁進入今日授課、簽到及點名。名冊可搜尋班級、學生或社團。
- 行政可設定候補及手動登記繳費。學生帳號可查自己的報名結果與繳費狀態。
- 已鎖定且尚未完成紙本作業的核銷可由行政填寫原因作廢。原快照保留在作廢紀錄，可更正後重新核算。正式核銷前應由會計與出納確認流程及 Excel 試印。

## 批次行政與 Excel 核銷

- **權限管理 → 批次匯入帳號**。下載 CSV 範本，填寫帳號、姓名、角色、班級、座號。支援 UTF-8 CSV 和試算表貼上，最多 200 筆。學生的班級、座號、姓名須符合所選學期的名冊。社團老師與班級導師的班級及座號留空。匯入不授予行政角色。
- **帳號啟用**。已有且已驗證的 Supabase Auth 電子郵件會立即綁定；既有試用帳號可用短帳號。其他電子郵件會列為待啟用。需要先在 Supabase Auth 建立並驗證登入帳號，或經學校已啟用的 Google 登入驗證身分，首次登入時才會開通。這個匯入流程不寄信、不發密碼。輸入錯誤可由行政取消待啟用設定。
- **社團與報名 → 報名錄取與上課名單**。選社團與操作，勾選後可批次錄取、不錄取、加入或退選。錄取與名單異動需指定生效日，加入與退選會留下異動紀錄。任何一筆不符條件時整批退回。
- **行政核銷 → 已鎖定核銷 → 匯出憑證及印領清冊**。Excel 以程式產生 A4 黏貼憑證與印領清冊的同頁版型，逐位教師、逐費率分列，包含授課日期、節數、金額及合計。憑證編號、預算科目、日期、簽證號、簽章及扣繳確認由承辦或出納填寫。簽到表維持獨立列印。

## 既有功能與試辦範圍

0.3.0 更新：異動管理新增編修及歷史紀錄，已確認代調課以新修訂保留原紀錄；待覆核編修維持待覆核。詳見 `升級至0.3.0.md`。

0.2.0 更新：本週課表及社團頁新增「批次新增週期課程」，提供日期區間、複選星期、時段、節數、教師、費率及排除日期。先預覽後整批交易新增；完全相同的課程略過，任何衝突則全批失敗。每批最多 200 次，不自動排除國定假日。

「課表與名冊」每列新增「修改／綁定帳號」。行政須確認學生身分，一個學生帳號同學期只能綁定一名學生。學生未綁定時，報名頁提供具體提醒並停用報名按鈕。

- 已實作：入口網、週課表、社團建立／報名／錄取、名冊 CSV、請假覆核、授課簽到與點名、學生增退與代調課、每週安排調整、分期核銷快照與列印、角色及學期設定。

- 尚待完成驗收：完整個人與班級 PDF 匯出、課程設定編輯與批次匯入、Email／推播、備份還原演練。請勿直接作正式財務核銷。
